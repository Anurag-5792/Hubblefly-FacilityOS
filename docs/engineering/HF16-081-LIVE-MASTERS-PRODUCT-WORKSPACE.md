# HF16-081 — Live Masters product workspace

Replaces the bare qualification form with a responsive FacilityOS-branded directory/editor, using the existing brand palette. Six real master kinds, no fabricated records or operational links. Existing protected deployment is not changed by this source candidate. No stock, role assignment or DELETE action is exposed. Company/site and warehouse selection come only from the same-origin POST session context, which projects the existing verified signed cookie; all business reads and writes still independently pass the existing SQL admission and authorization. No migration, signer, session verifier, credential, middleware or SQL change.

The directory explicitly limits results to the current API's 100-record response and uses server ID search plus local filtering. It does not pretend to offer whole-database name search. Item descriptions, richer HR details, certified locations, stock and role grants require separate admitted data contracts. Unconfirmed mutation references are retained in sessionStorage for the current tab; never auto-retried. The history reconciliation only unlocks when the original request appears with its expected revision and action. Session storage is not a cross-tab global write fence; server idempotency/CAS controls remain authoritative.

Source candidate only: exact-head CI, browser rendering and bounded session-context security review are required before a new qualification release admission, hosted smoke tests and alias switch. No new owner signature for routine in-scope engineering under the accepted standing continuation.
